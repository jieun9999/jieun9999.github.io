## 들어가며

**위블로그 커스텀 도메인 도입기 · 1편**

위블로그는 사용자가 선택한 주제와 키워드로 블로그 글을 자동 생성하고 발행하는 서비스입니다.

그런데 글을 정상적으로 발행했는데도 구글 검색에 나오지 않는 경우가 많았습니다. 페이지는 잘 열리고 사이트맵도 제출했지만, Google Search Console에서는 상당수 글이 색인되지 않은 상태였습니다.

원인을 조사하기 위해 플랫폼에서 제공하는 기본 서브도메인과 사용자가 직접 연결한 커스텀 도메인을 비교했습니다.

2026년 7월 21일 조사에서는 기본 서브도메인의 글 1,784개 중 62개가 색인됐습니다. 반면 커스텀 도메인을 사용하는 블로그 한 곳에서는 90개 중 61개가 색인돼 있었습니다.

두 집단의 조건이 같지 않아 도메인 유형만으로 생긴 차이라고 볼 수는 없었습니다. 다만 그대로 두기에는 차이가 컸습니다.

이후 기본 도메인을 변경하고, 색인이 잘 진행되지 않던 사이트의 주소를 옮겨보면서 검색 유입을 원하는 사용자에게 커스텀 도메인을 권장하기로 했습니다.

## 1. 글이 안 보인다는 것은 어떤 상태일까?

먼저 글이 정상적으로 발행됐는데 왜 검색에서는 찾을 수 없는지 확인해야 했습니다.

검색에 나오지 않는다고 해서 모두 같은 문제가 있는 것은 아닙니다.

| 단계 | 확인할 내용 |
|---|---|
| 발행 | URL로 접속했을 때 페이지가 정상적으로 열리는가? |
| 크롤링 | 구글의 크롤러가 페이지를 방문했는가? |
| 색인 | 구글이 해당 페이지를 검색 색인에 포함했는가? |
| 검색 노출 | 사용자가 검색했을 때 결과에 표시되는가? |

예를 들어 사이트맵에 글 주소를 등록했다고 구글이 그 글을 바로 읽는 것은 아닙니다. 구글이 페이지를 읽었다고 반드시 색인하는 것도 아닙니다.

따라서 문제가 발생한 단계를 구분해야 했습니다.

이를 위해 Google Search Console(GSC)의 URL 검사 결과와 서버의 Googlebot 접근 기록을 확인했습니다.

GSC에서는 구글이 URL을 인식하고 있는지, 마지막으로 언제 크롤링했는지, 검색 색인에 포함했는지 등을 확인할 수 있습니다.

이 과정에서 글이 단순히 색인에서 제외된 것뿐 아니라, 구글에 아직 알려지지 않은 URL도 상당히 많다는 사실을 발견했습니다.

## 2. 서브도메인과 커스텀 도메인의 색인 결과가 크게 달랐습니다

당시 위블로그는 사용자가 별도 도메인을 구매하지 않아도 블로그를 시작할 수 있도록 다음과 같은 기본 주소를 제공했습니다.

`myblog.workb.xyz`

사용자는 블로그를 만들자마자 글을 발행할 수 있었습니다. 하지만 이렇게 생성된 블로그들이 검색엔진에 얼마나 등록되고 있는지는 별도로 확인할 필요가 있었습니다.

7월 21일, GSC URL 검사 결과를 수집해 기본 서브도메인과 커스텀 도메인을 비교했습니다.

| 비교 대상 | 조사한 글 | 색인된 글 | 색인율 |
|---|---:|---:|---:|
| `*.workb.xyz` | 1,784개 | 62개 | 약 3.5% |
| `babynote.blog` | 90개 | 61개 | 약 67.8% |

특히 기본 서브도메인에서 조사한 1,784개 글 중 1,566개는 구글에 알려지지 않은 URL로 기록돼 있었습니다.

색인 대상에서 제외된 글도 있었지만, 아예 발견되지 않은 글이 더 많았던 것입니다.

반면 `babynote.blog`는 7월 13일 첫 글을 발행한 비교적 새로운 블로그였습니다. 그런데 불과 8일 뒤 조사에서 90개 중 61개가 색인돼 있었습니다.

처음에는 블로그를 만든 지 얼마 되지 않아 시간이 더 필요한 것일 수도 있다고 생각했습니다. 하지만 두 결과를 함께 보면 단순히 운영 기간만으로 설명하기는 어려웠습니다.

한 사이트에서만 나타난 현상인지 확인하기 위해 조사 범위를 넓혔습니다. 7월 23일에는 커스텀 도메인 여섯 곳 모두에서 24시간 이내의 색인 사례를 확인했습니다.

그렇다고 여섯 사이트의 모든 글이 하루 만에 색인됐다는 뜻은 아닙니다. 각 사이트에서 색인된 글을 확인했다는 의미입니다.

또한 이 비교에는 분명한 한계가 있습니다.

기본 서브도메인 1,784개는 전체 조사가 완료되기 전의 중간 결과였고, 커스텀 도메인 90개는 한 사이트의 전체 글이었습니다. 도메인별 운영 기간과 글의 주제, 품질, 발행 빈도도 완전히 같지 않았습니다.

따라서 **커스텀 도메인이라서 색인율이 높았다고 증명한 실험은 아닙니다.**

다만 같은 생성 시스템에서 만들어진 블로그들이 주소에 따라 상당히 다른 결과를 보인다는 사실은 추가 조사가 필요한 이유가 됐습니다.

## 3. 기본 주소를 바꿔도 문제는 해결되지 않았습니다

당시에는 `.blog` 확장자가 블로그 서비스에 더 적합하지 않을까 생각했습니다.

그래서 7월 23일부터 기본 도메인을 `workb.xyz`에서 `witim.blog`로 변경했습니다.

기존 주소가 다음과 같았다면,

`myblog.workb.xyz`

변경 후에는 아래 주소를 사용하도록 했습니다.

`myblog.witim.blog`

도메인을 바꾸면서 DNS와 서버 라우팅만 수정한 것은 아닙니다.

정적 페이지에 들어가는 대표 URL(canonical)과 사이트맵도 새 주소로 변경해야 했습니다. 이 값들은 빌드할 때 생성되므로, DNS만 변경하면 이전 주소가 HTML에 남을 수 있었습니다.

실제로 7월 28일에는 랜딩 페이지에서 canonical이 누락돼 구글이 이전 `workb.xyz` 주소를 대표 URL로 선택한 문제를 발견하고 수정했습니다.

하지만 이 문제를 해결했다고 블로그 전체의 색인 문제가 사라진 것은 아니었습니다.

8월 1일에는 `witim.blog` 아래에서 이미 색인됐던 페이지들이 다시 제외되는 현상을 확인했습니다.

8월 7일, 커스텀 도메인과 기본 서브도메인의 사이트 대표 주소가 색인돼 있는지 비교했습니다.

| 비교 대상 | 조사한 사이트 | 색인된 사이트 대표 URL |
|---|---:|---:|
| 커스텀 도메인 | 19개 | 17개 |
| 기본 서브도메인 | 15개 | 0개 |

이번에는 개별 글이 아니라 각 블로그의 대표 URL을 조사했습니다. 따라서 앞서 조사한 글 단위 색인율과 직접 비교할 수는 없습니다.

`robots.txt`, canonical, 페이지 응답, 기존 주소의 리다이렉트도 확인했습니다. GSC에 표시된 수동 조치나 보안 문제는 없었습니다.

그러나 여러 서브도메인이 비슷한 시점에 색인에서 제외된 정확한 원인까지 알아내지는 못했습니다.

콘텐츠의 유사성이나 품질, 사이트별로 축적된 검색 신호 등 다른 요인이 영향을 미쳤을 가능성도 남아 있었습니다.

확인할 수 있었던 것은 한 가지였습니다.

**기본 주소를 `.xyz`에서 `.blog`로 바꾸는 것만으로는 문제가 해결되지 않았습니다.**

## 4. 색인이 잘되지 않던 도메인의 주소를 직접 바꿔봤습니다

커스텀 도메인이라고 항상 좋은 결과가 나온 것도 아닙니다.

당시 운영하던 두 사이트에서 글이 잘 크롤링되지 않는 문제가 있었습니다.

- `btc-btc-btc.shop`
- `smr-smr-smr-smr.shop`

8월 11일 기준으로 첫 번째 사이트의 사이트맵에 등록된 URL 76개 중 10개는 이미 색인돼 있었습니다. 사이트 전체가 색인되지 않은 것은 아니었습니다.

문제는 그 이후 다른 글들이 충분히 크롤링되지 않는다는 점이었습니다.

18일간의 서버 접근 기록을 확인했습니다.

| 조사 대상 | 사이트맵 요청 | 크롤링된 서로 다른 글 URL |
|---|---:|---:|
| 비트코인 사이트 | 34회 | 6개 |
| SMR 사이트 | 28회 | 5개 |

구글이 사이트맵을 요청하고는 있었지만, 실제 글 페이지까지 충분히 방문하지는 않는 것으로 보였습니다.

8월 11일에는 비트코인 사이트의 글 9개에 대해 색인을 요청하고 변화를 추적했습니다. 비슷한 시기에 발행한 다른 글도 비교 대상으로 남겨뒀습니다.

서버 로그에서는 Googlebot이라는 이름만 확인하지 않고 공식 IP 대역과 대조해 실제 구글 크롤러의 요청인지 확인했습니다.

8월 18일까지 여섯 차례 측정했지만, 색인을 요청한 9개 글에서는 크롤링과 색인이 모두 확인되지 않았습니다.

### 콘텐츠는 유지하고 도메인만 이전하기로 했습니다

8월 18일, 조사 결과를 정리한 뒤 두 사이트의 도메인을 변경했습니다.

| 기존 주소 | 변경한 주소 |
|---|---|
| `btc-btc-btc.shop` | `coinmanual.blog` |
| `smr-smr-smr-smr.shop` | `powerinsight.blog` |

![2026년 8월 18일 도메인 이전을 결정할 당시 기록한 조사 결과](/images/custom-domain-indexing/tld-observation-2026-08-18.png)

새 글을 작성하거나 기존 내용을 다시 생성하지 않았습니다. 같은 콘텐츠를 새 도메인에서 제공하도록 하고, canonical과 사이트맵, 기존 주소의 리다이렉트를 수정했습니다.

비트코인 사이트에서는 기존에 추적하던 16개 글의 URL 경로도 그대로 유지했습니다.

이전 직후에는 새 도메인의 조사 대상에서 크롤링과 색인이 확인되지 않았습니다.

그런데 다음 날인 8월 19일, 새 도메인에서 색인이 다시 진행되는 것을 확인했습니다.

그동안 글을 여러 개 발행하고 색인을 요청해도 변화가 없었던 상황이었기 때문에 눈여겨볼 결과였습니다.

다만 이것을 `.shop` 도메인이 검색에 불리하다는 증거로 해석해서는 안 됩니다.

이번 변경에는 서로 다른 조건이 동시에 포함돼 있었습니다.

- `.shop`에서 `.blog`로 확장자를 변경했습니다.
- `btc-btc-btc`처럼 반복된 도메인 이름도 함께 변경했습니다.
- 기존 주소를 새 주소로 이전하면서 검색엔진에 전달되는 주소 정보도 정리했습니다.
- 시간 경과에 따라 색인이 진행됐을 가능성도 배제할 수 없었습니다.

이 때문에 어떤 요인이 색인 회복에 영향을 줬는지는 구분할 수 없습니다. 장기적으로 색인이 유지되는지, 전체 글이 얼마나 색인되는지까지 검증한 결과도 아니었습니다.

구글 역시 [공식 FAQ](https://developers.google.com/search/help/site-position-in-search-faq)에서 최상위 도메인 확장자 자체가 검색 순위를 결정하는 요소는 아니라고 설명합니다.

제가 확인한 것은 **해당 두 사이트에서 콘텐츠를 유지하고 주소를 변경한 뒤 색인이 다시 진행됐다는 사실**까지입니다.

## 5. 이 결과를 실제 제품에 어떻게 반영했을까?

원인을 완전히 밝혀내지는 못했지만, 사용자에게 어떤 주소를 추천할지 결정해야 했습니다.

그전까지 커스텀 도메인은 블로그에 원하는 주소를 붙이는 부가 기능에 가까웠습니다.

하지만 조사 결과를 보면서 검색 유입을 목적으로 블로그를 운영하는 사용자에게는 도메인 선택이 더 중요한 문제가 됐습니다.

그래서 도메인 추천 방식을 변경했습니다.

### 커스텀 도메인을 적극적으로 안내하기로 했습니다

사용자가 위블로그를 처음 체험하는 단계에서는 기본 서브도메인을 계속 사용할 수 있도록 했습니다.

블로그를 시험해 보려고 시작한 사람에게 처음부터 도메인 구매를 요구할 필요는 없었기 때문입니다.

반면 장기적으로 검색 유입을 만들려는 사용자에게는 직접 소유한 커스텀 도메인을 권장하기로 했습니다.

또한 당시 운영 표본에서 색인 사례가 확인됐던 `.blog`, `.site`, `.live`를 추천 목록에 두고, 문제가 있었던 `.shop`은 자동 추천에서 제외했습니다.

다만 `.shop` 도메인을 직접 검색해 구매하는 것까지 막지는 않았습니다.

이것은 구글이 특정 확장자에 부여한 공식적인 등급을 따른 결정이 아닙니다. 위블로그에서 관찰한 사례를 근거로 추천 기준을 보수적으로 조정한 것입니다.

### 도메인을 변경해도 기존 글 주소가 이어지도록 했습니다

이미 사용 중인 도메인을 다른 커스텀 도메인으로 바꾸는 기능도 보완했습니다.

기존에는 한 블로그에 연결된 여러 도메인이 같은 콘텐츠를 `200 OK`로 제공할 수 있었습니다. 이 상태에서 새 도메인을 추가하면 기존 주소와 새 주소가 동시에 같은 글을 보여줄 수 있었습니다.

이를 변경해 대표 도메인 하나에서 콘텐츠를 제공하고, 이전 도메인은 같은 경로의 새 주소로 `301` 리다이렉트하도록 했습니다.

도메인 이전에서는 다음 사항을 확인했습니다.

1. 새 주소에서 HTTPS와 페이지가 정상적으로 열리는지
2. canonical과 사이트맵이 새 주소를 가리키는지
3. 기존 글의 주소가 새 도메인의 동일한 경로로 이동하는지
4. CDN에 남은 이전 응답 캐시가 제거됐는지
5. GSC에서 새 도메인의 소유권 확인과 사이트맵 제출이 완료됐는지

도메인 구매만 완료된 상태와 블로그 주소 이전이 완료된 상태는 다릅니다.

사용자와 검색엔진이 새로운 대표 주소로 정상적으로 접근할 수 있어야 이전이 끝났다고 볼 수 있었습니다.

## 6. 커스텀 도메인이 검색 노출을 보장하는 것은 아닙니다

이번 조사에서 커스텀 도메인을 사용하는 블로그들이 더 좋은 색인 결과를 보였고, 주소를 변경한 뒤 색인이 회복된 사례도 확인했습니다.

하지만 이것만으로 커스텀 도메인이 색인율을 높인다고 증명할 수는 없습니다.

사이트마다 운영 기간, 콘텐츠 주제, 글의 품질, 발행 빈도 등 여러 조건이 달랐기 때문입니다.

또한 **색인됐다는 것은 검색 상위에 노출됐다는 뜻이 아닙니다.**

실제 검색 유입이 발생했는지 판단하려면 색인 여부뿐 아니라 어떤 검색어에서 노출됐는지, 얼마나 클릭됐는지도 확인해야 합니다.

따라서 커스텀 도메인 연결만으로 검색 성과를 해결했다고 보지는 않습니다.

다만 위블로그를 사용하는 사람이 자신의 주소로 블로그를 장기 운영할 수 있도록 지원하고, 해당 주소의 검색 상태를 지속적으로 확인할 수 있게 하는 것은 제품에서 중요하다고 판단했습니다.

## 마무리하며

처음에는 글을 정상적으로 발행했는데도 검색에서 찾을 수 없는 이유를 조사하는 작업이었습니다.

기본 서브도메인과 커스텀 도메인의 색인 결과를 비교했고, 기본 도메인을 변경해도 같은 문제가 반복되는 것을 확인했습니다. 이후 색인이 잘 진행되지 않던 커스텀 도메인 두 개를 이전하면서 검색 결과의 변화를 관찰했습니다.

실험 조건이 완전히 통제되지 않았기 때문에 도메인이 색인 결과에 얼마나 영향을 줬는지는 단정할 수 없습니다.

그럼에도 실제 운영 데이터에서 반복해서 나타난 차이를 근거로, 위블로그에서는 검색 유입을 목표로 하는 사용자에게 커스텀 도메인을 권장하기로 했습니다.

**검색 색인 문제를 완전히 해결한 사례라기보다, 확인할 수 있는 데이터를 바탕으로 제품의 도메인 추천 기준을 바꾼 경험에 가깝습니다.**

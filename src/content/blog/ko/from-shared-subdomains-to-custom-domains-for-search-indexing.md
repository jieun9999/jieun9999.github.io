## 들어가며

위블로그는 사용자의 주제와 키워드로 글을 생성·발행하는 서비스입니다. 글은 정상적으로 열렸지만, 검색엔진이 가져가지 않거나 색인에서 제외하는 문제가 있었습니다.

블로그 서비스에는 `.blog`가 더 나을 것으로 기대해 기본 주소를 `workb.xyz`에서 `witim.blog`로 바꿨지만, 색인 문제를 해결하는 데 큰 의미는 없었습니다. 반면 블로그별 커스텀 도메인에서는 다른 결과가 나타났습니다.

이 글은 그 차이를 조사하고 도메인 이전을 시도하면서, **검색 유입을 목표로 하는 사용자에게 커스텀 도메인을 권장하게 된 과정**을 정리합니다.

## 먼저 발행·크롤링·색인·노출을 나눴습니다

처음에는 검색에 나오지 않는 현상을 모두 색인 문제로 묶기 쉬웠습니다. 하지만 어디에서 멈췄는지에 따라 다음 행동이 달랐습니다.

| 단계 | 확인하려는 사실 | 사용한 근거 |
| --- | --- | --- |
| 발행 | 공개 URL에서 페이지가 정상적으로 열리는지 | HTTP 응답, 렌더된 HTML |
| 발견·크롤링 | 검색엔진이 URL을 알고 실제로 가져갔는지 | GSC URL 검사, Googlebot 접근 로그 |
| 색인 | 가져간 페이지가 검색 색인에 포함됐는지 | GSC URL 검사 결과 |
| 검색 노출 | 검색어에 대해 결과가 표시됐는지 | GSC 검색 실적, 실제 검색 결과 |

GSC는 Google Search Console의 약자입니다. URL 검사에서는 Google이 알고 있는 해당 URL의 색인 상태와 마지막 크롤링 시점 등을 확인했습니다. 이 결과는 방금 배포한 페이지를 실시간으로 다시 검사한 결과와는 구분해야 합니다.

사이트맵 제출은 URL을 알리는 수단입니다. 제출했다고 바로 크롤링하거나 색인하는 것은 아니며, 색인됐다고 특정 검색어에서 상단에 노출되는 것도 아닙니다. Google도 [검색의 작동 과정](https://developers.google.com/search/docs/fundamentals/how-search-works)에서 크롤링·색인·검색결과 제공을 별도 단계로 설명합니다.

이 구분 덕분에 “글을 더 발행하면 해결되는가”보다 “이미 발행한 글에 검색엔진이 도달하고 있는가”를 먼저 볼 수 있었습니다.

## workb.xyz에서 발견한 큰 차이

초기에는 각 블로그에 `{slug}.workb.xyz` 형태의 서브도메인을 제공했습니다. 별도 도메인을 구매하지 않아도 바로 시작할 수 있는 구조였습니다.

7월 21일, 글 URL을 GSC URL 검사 API로 조회하면서 커스텀 도메인을 쓰는 블로그와 비교했습니다. 주소 형태에 따라 글의 색인 상태가 달라지는지 조사한 결과는 다음과 같습니다.

| 비교 대상 | 조사한 글 URL | 색인된 글 | 색인율 |
| --- | ---: | ---: | ---: |
| `*.workb.xyz` 서브도메인 | 1,784건 | 62건 | 약 3.5% |
| `babynote.blog` 커스텀 도메인 | 90건 | 61건 | 약 67.8% |

서브도메인 쪽은 전체 글의 조사가 끝난 상태가 아니었습니다. API 조회 한도로 여러 날에 나눠 조사하던 중간 결과였고, 커스텀 도메인 쪽은 한 사이트의 90건을 모두 확인한 값입니다. 같은 생성 파이프라인을 사용했지만, 같은 글을 무작위로 나눠 배치한 통제 실험은 아니었습니다.

그 한계를 감안해도 차이는 컸습니다. 서브도메인에서 조사한 1,784건 중 1,566건은 검사 결과상 Google에 알려지지 않은 URL로 기록돼 있었습니다. 콘텐츠를 읽고 낮게 평가한 경우만 있는 것이 아니라, **아직 가져가지 않은 글이 대다수인 상태**였습니다.

반면 `babynote.blog`는 7월 13일 첫 글을 발행한 블로그였습니다. 운영을 시작한 지 오래되지 않았는데도 7월 21일 조사에서 글의 약 68%가 색인됐습니다. 단순히 새 블로그라서 모두 같은 기간을 기다려야 한다는 설명으로는 두 결과를 설명하기 어려웠습니다.

한 사이트에서만 나타난 결과인지 확인하기 위해 비교 범위를 넓혔습니다. 7월 23일 후속 조사에서는 커스텀 도메인 6개 모두에서 24시간 안에 색인을 확인했습니다. 이 수치는 **6개 사이트에서 색인 성공을 확인했다는 의미**이며, 각 사이트의 모든 글이 하루 만에 색인됐다는 뜻은 아닙니다.

이때부터 커스텀 도메인은 부가적인 꾸미기 기능보다 검색 운영에 필요한 선택에 가까워졌습니다. 다만 무료 체험 단계까지 없앨 수는 없었습니다. 사용자가 글을 만들어 보고 판단할 기본 주소는 유지하되, 검색 성과를 기대하는 단계에서는 자기 도메인을 안내할 필요가 있었습니다.

## witim.blog로 바꾼 뒤에도 문제가 반복됐습니다

`.blog`가 블로그 서비스에 더 적합할 것으로 기대해, 7월 23일부터 기본 도메인을 `workb.xyz`에서 `witim.blog`로 바꿨습니다. 블로그별 주소는 여전히 공유 도메인 아래의 서브도메인이었습니다.

이전 과정에서는 주소를 바꾸는 것 외에도 확인할 항목이 있었습니다. 정적 페이지의 canonical과 사이트맵은 빌드할 때 만들어지므로, DNS와 서버 라우팅만 바꿔서는 새 주소가 반영되지 않았습니다. 새 도메인을 먼저 병행해서 열고 인증서와 라우팅을 확인한 뒤 대표 주소와 구주소의 리디렉션을 전환했습니다.

랜딩 페이지에는 별도의 canonical 누락도 있었습니다. 7월 28일, 랜딩 페이지가 검색에서 제외되는 원인을 조사하면서 새 랜딩의 사용자 선언 canonical이 없고 Google이 옛 `workb.xyz`를 대표 URL로 선택한 것을 확인해 수정했습니다. 이 문제와 이후 블로그 서브도메인들의 색인 제외는 구분해서 봐야 했습니다.

8월 1일에는 `witim.blog` 아래에서 이미 색인됐던 페이지들이 제외되는 현상을 관찰했습니다. 영향 범위를 확인하기 위해 8월 7일 커스텀 도메인과 플랫폼 서브도메인의 **사이트 루트 URL**을 비교했습니다.

| 비교 대상 | 조사한 사이트 루트 URL | 색인된 루트 URL |
| --- | ---: | ---: |
| 커스텀 도메인 | 19개 | 17개 |
| 글 수 기준 상위 플랫폼 서브도메인 | 15개 | 0개 |

앞 절의 글 단위 색인율과는 측정 단위가 다릅니다. 이 표만으로 커스텀 도메인 글의 89%가 색인됐다고 해석할 수는 없습니다. 색인되지 않은 커스텀 도메인 두 곳에서도 각각 리디렉션과 이전 크롤링 시점의 404가 확인됐습니다.

이 조사에서는 robots, canonical, 페이지 응답, 구주소 리디렉션을 확인했습니다. GSC의 수동 조치와 보안 문제 화면에서도 감지된 문제는 없었습니다. 따라서 “수동 페널티를 받았다”고 설명할 근거는 없었습니다. 여러 사이트가 비슷한 시점에 제외된 이유가 콘텐츠 패턴인지, 도메인에 축적된 신호인지까지 확정할 수는 없었습니다.

그럼에도 제품 결정을 위한 근거는 쌓였습니다. **기본 도메인을 `.xyz`에서 `.blog`로 한 번 바꾸는 것만으로는 검색 운영의 문제가 해결되지 않았고, 같은 플랫폼에서 커스텀 도메인을 사용하는 사이트들은 다른 결과를 보였습니다.**

## .shop 두 사이트는 같은 콘텐츠를 옮긴 뒤 색인이 회복됐습니다

커스텀 도메인에서도 예외가 있었습니다. `btc-btc-btc.shop`과 `smr-smr-smr-smr.shop`입니다. 두 사이트는 색인이 무너지는 현상을 보였고, 다른 커스텀 도메인보다 글에 대한 크롤링이 적었습니다.

여기서도 사이트 전체가 완전히 색인 0인 상태와는 구분해야 합니다. 크롤링 부진을 조사하던 8월 11일에는 비트코인 사이트의 사이트맵 URL 76건 중 10건이 색인된 상태였습니다. 문제는 일부 페이지가 남아 있는 동안에도 다른 글의 발견·크롤링·색인이 진행되지 않는다는 점이었습니다.

18일간의 접근 기록을 보면 비트코인 사이트의 사이트맵에는 34회 요청이 있었지만, 크롤링된 고유 글 URL은 6개였습니다. SMR 사이트도 사이트맵 요청은 28회였지만 고유 글 URL은 5개였습니다. 사이트맵을 전혀 찾지 못하는 상황보다는, 그 안의 글을 충분히 가져가지 않는 상황에 가까웠습니다.

이를 더 확인하려고 8월 11일 비트코인 사이트의 글 9건에 GSC 색인 생성을 요청하고, 비슷한 시기에 발행한 미제출 글은 비교 대상으로 남겼습니다. Googlebot이라는 User-Agent만 믿지 않고 공식 IP 대역과 대조해 실제 크롤러 요청을 확인했습니다. 8월 18일까지 여섯 차례 측정했지만, 요청한 9건은 크롤링과 색인이 모두 0건이었습니다.

도메인을 옮기기 전, 8월 18일 조사 결과와 판단을 이슈에 정리했습니다. 아래 표의 6/6·5/5·5/5·0/2는 글 URL 수가 아니라 TLD별 조사 사이트 중 색인을 확인한 사이트 수입니다. 앞서 비트코인 사이트에 일부 색인된 URL이 남아 있던 시점과도 구분해서 봐야 합니다.

![2026년 8월 18일 도메인 이전을 결정한 이슈 기록입니다. 색인 요청 9건의 크롤링·색인 결과와 .blog 6/6, .site 5/5, .live 5/5, .shop 0/2의 사이트별 관찰 결과를 정리했습니다.](/images/custom-domain-indexing/tld-observation-2026-08-18.png)

이 기록을 바탕으로 `.shop`과 반복형 도메인 이름을 함께 바꾸기로 했습니다. 이미지에 적힌 TLD 평판과 크롤 수요의 관계는 당시의 가설이며, 이 비교로 원인이 확인된 것은 아닙니다.

다음 실험은 콘텐츠를 유지한 채 주소를 옮기는 것이었습니다.

| 기존 도메인 | 새 도메인 | 이전일 |
| --- | --- | --- |
| `btc-btc-btc.shop` | `coinmanual.blog` | 2026-08-18 |
| `smr-smr-smr-smr.shop` | `powerinsight.blog` | 2026-08-18 |

비트코인 사이트는 이전부터 추적하던 16개 URL의 경로를 그대로 유지했습니다. 새 주소에서 본문을 다시 쓰는 대신, 같은 콘텐츠를 서빙하도록 연결하고 canonical·사이트맵·리디렉션을 새 주소에 맞췄습니다.

8월 18일 이전 직후에는 새 도메인의 조사 대상이 모두 크롤링 0건·색인 0건이었습니다. 그리고 다음 날인 **8월 19일, 새 도메인에서 색인이 정상적으로 진행되는 것을 확인했습니다.** 전체 글의 색인 완료율이나 장기 유지 여부까지 검증한 결과는 아닙니다.

여기서 확인한 것은 **콘텐츠를 유지한 도메인 이전 후 색인이 회복됐다는 사실**입니다. `.shop`이라는 최상위 도메인(TLD)과 `btc-btc-btc` 같은 반복형 이름을 동시에 바꿨기 때문에, 둘 중 어느 요인이 영향을 줬는지는 분리하지 못했습니다. 이전 신호의 정리와 시간 경과도 함께 있었으므로 원인을 TLD 하나로 확정할 수는 없습니다.

Google의 [검색 순위 FAQ](https://developers.google.com/search/help/site-position-in-search-faq)도 TLD 자체로 검색 성능이 결정되지 않는다고 설명합니다. 이 경험은 모든 `.shop`이 색인에서 제외된다거나, `.blog`를 구매하면 색인이 보장된다는 일반 법칙이 아닙니다.

## 관찰 결과를 도메인 추천과 이전 기능에 반영했습니다

원인을 완전히 분리하지 못했다고 해서 운영 결정을 계속 미룰 수는 없었습니다. 같은 플랫폼에서 반복해서 확인한 결과를 기준으로, 사용자에게 권할 주소와 이전 방식을 조정했습니다.

먼저 도메인 추천 기준을 조정했습니다. `.shop`을 자동 도메인 추천에서 제외하고, 당시 운영 표본에서 색인이 확인된 `.blog`·`.site`·`.live`를 권장하도록 바꿨습니다. 수동 검색 자체를 금지하지는 않았으며, 구매 화면에는 반복형 이름을 피하라는 안내도 넣었습니다. 이는 Google의 공식 TLD 등급표가 아니라 **해당 서비스의 실측에 따른 보수적인 추천 정책**입니다.

이와 함께 커스텀 도메인에서 다른 커스텀 도메인으로 옮기는 경로도 보완했습니다. 기존 코드는 한 사이트에 연결된 도메인들을 같은 블록에 넣어 모두 `200`으로 서빙했습니다. 새 도메인만 추가하면 옛 주소도 같은 콘텐츠를 계속 제공하는 구조였습니다.

이를 대표 도메인은 콘텐츠를 제공하고, 이전 도메인은 경로를 유지해 대표 도메인으로 `301` 응답을 주도록 바꿨습니다. 실제 이전에서는 다음 항목을 함께 확인했습니다.

1. 새 도메인에서 HTTPS와 페이지 응답이 정상인지 확인했습니다.
2. 정적 파일을 다시 빌드해 canonical과 사이트맵을 새 주소로 맞췄습니다.
3. 옛 주소의 글이 새 주소의 같은 글로 리디렉션되는지 확인했습니다.
4. CDN에 남아 있던 옛 `200` 응답 캐시를 제거했습니다.
5. GSC 새 속성의 소유권 확인, 사이트맵 제출, 주소 변경을 처리했습니다.

Google의 [사이트 이전 가이드](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes) 역시 새 URL의 canonical, 영구 리디렉션, 사이트맵 등 이전 신호를 정리하도록 안내합니다. 도메인 구매가 끝났는지보다 **검색엔진과 사용자가 같은 대표 주소에 도달하는지**가 완료 기준이었습니다.

구매부터 DNS·인증서 연결까지 자동화한 과정은 [커스텀 도메인 연결 자동화 글](/ko/blog/automating-custom-domain-connection-a-delegation-gated-pipeline/)에 따로 정리했습니다. 이 글의 중심은 그 기능을 왜 검색 운영의 기본 권장 사항으로 보게 됐는지입니다.

## 신생 도메인도 콘텐츠로 검색 기회를 만들 수 있습니다

이 실험에서 함께 남기고 싶은 점은 새 도메인이라는 이유만으로 검색 가능성을 포기할 필요는 없다는 것입니다. `babynote.blog`는 첫 글 발행 8일 뒤 조사에서 90건 중 61건이 색인됐고, `.shop`에서 이전한 두 새 도메인에서도 색인 회복을 확인했습니다.

운영 중에는 신생 도메인의 글이 검색결과 상단에 노출되는 사례도 확인했습니다. 다만 이 글에 제시한 URL 검사 수치가 그 순위를 증명하는 것은 아닙니다. 색인 회복은 앞서 살펴본 도메인 이전 실험의 결과이고, 상단 노출은 별도로 확인한 운영 경험입니다. 특정 순위와 유지 기간을 수치로 제시하지는 않습니다.

이 경험을 통해 **신생 도메인이어도 검색 의도에 맞는 양질의 콘텐츠라면 색인뿐 아니라 상단 노출도 가능하다**고 판단했습니다. 콘텐츠 품질만으로 순위가 결정된다는 뜻은 아닙니다. 도메인을 바꾸는 것과 함께 독자가 실제로 찾는 질문에 답하는 글을 만드는 일이 필요했습니다.

제가 담당한 생성 과정에서도 품질을 글의 길이나 발행량으로만 보지 않았습니다. 질문에 직접 답하는 내용, 주장을 확인할 수 있는 참고 자료, 독자가 필요한 부분을 찾을 수 있는 구성을 중요하게 봤습니다. 이런 기준이 개별 글의 상단 노출을 얼마나 설명하는지까지 분리해 측정한 것은 아니지만, 주소를 바꾼 뒤에도 계속 유지해야 할 작업이었습니다.

따라서 결과를 볼 때도 색인 여부에서 멈추지 않고, 어떤 검색어로 노출됐는지와 실제 클릭이 발생했는지를 이어서 확인해야 합니다. 커스텀 도메인은 콘텐츠를 대신하는 해결책이 아니라, 콘텐츠가 검색에서 평가받고 운영 이력을 쌓아갈 주소입니다.

## 마무리하며

`workb.xyz`에서 `witim.blog`로 옮긴 뒤에도 색인 문제는 반복됐습니다. 반면 커스텀 도메인에서는 같은 플랫폼으로 만든 블로그가 색인됐고, 색인이 불안정했던 `.shop` 두 사이트도 콘텐츠를 유지한 채 `.blog`로 이전한 뒤 회복을 확인했습니다.

이 PoC를 거치며 검색 유입을 목표로 하는 사용자에게는 커스텀 도메인을 반드시 권장해야 한다는 결론을 내렸습니다. 체험용 주소로 글을 만들어 보는 단계와, 자기 주소에서 검색 성과를 쌓는 단계를 제품에서 구분해야 했습니다.

동시에 도메인 이전만으로 콘텐츠 품질이나 검색 순위까지 해결되지는 않습니다. 신생 도메인도 좋은 콘텐츠로 검색 기회를 만들 수 있지만, 그 가능성을 실제 성과로 판단하려면 크롤링·색인·노출·클릭을 각각 확인해야 합니다. 제가 남기고 싶은 것은 특정 확장자의 우열보다, **관찰한 검색 결과를 도메인 추천과 운영 기능의 결정으로 연결한 과정**입니다.

## 관찰한 구성

타임아웃 상황과 해결 방향을 제시한 뒤 데이터 구조, 쿼리, 실행 계획으로 원인을 설명한다. 대안 선택과 개발 환경 검증을 거쳐 운영 적용으로 이어진다. 첫 테스트의 실패와 운영 중 추가로 드러난 문제도 다음 판단에 연결한다.

## 가져올 편집 원칙

가설을 독자가 판단할 수 있도록 필요한 증거를 먼저 놓는다. 각 시도에서 무엇을 배웠는지 설명한다. 개발 환경에서 확인한 효과와 운영에 적용하면서 확인한 결과를 구분한다.

deadlock, 인앱 로그인, 도메인 연결, 배포 장애에 적합하다. 관찰과 추론의 연결을 점검하고 재현 조건과 검증 범위를 밝힌다. 참고 글의 특정 DB 동작을 일반 법칙으로 가져오거나, 시도하지 않은 대안을 실패담으로 추가하지 않는다.
